SPRINT 02

Onderzoek & AI-ontwikkeling

Van het vergelijken van AI-modellen tot het programmeren en verbeteren van een werkende LLM voor onze interactieve teddybeer.

SAMENVATTING

Tijdens deze sprint heb ik onderzoek gedaan naar verschillende AI-modellen en mijn bevindingen vastgelegd in een researchdocument. Ook heb ik meegewerkt aan het opstellen van epics en user stories in GitLab. Samen met Thayna heb ik vervolgens aan de AI gewerkt, waarbij ik de LLM in Python heb opgezet, getest en verbeterd. 01 / DOEL

Mijn doel

Tijdens deze sprint wilde ik onderzoeken welke AI-modellen geschikt waren voor ons prototype en vervolgens een werkende LLM ontwikkelen.

Ons concept is een AI-companion in de vorm van een teddybeer. Het doel is dat kinderen vragen kunnen stellen en op een eenvoudige, vriendelijke manier antwoord krijgen.

Voor mij was het belangrijk dat de AI niet alleen technisch werkte, maar ook op een manier reageerde die bij de teddybeer past.

02 / MIJN BIJDRAGE

Mijn rol binnen het project

Tijdens deze sprint hield ik me bezig met het onderzoeken van AI-modellen, het uitwerken van user stories en het ontwikkelen van de LLM.

Samen met Thayna werkte ik aan het AI-gedeelte van ons prototype. Mijn bijdrage bestond onder andere uit het schrijven en aanpassen van Python-code, het testen van de antwoorden en het toevoegen van nieuwe functionaliteiten.

Ook heb ik mijn wijzigingen vastgelegd in GitLab, zodat we verder konden werken met dezelfde versie van de code.

03 / ONDERZOEK

Mijn researchdocument

Voordat we begonnen met programmeren, heb ik onderzoek gedaan naar verschillende AI-modellen die we konden gebruiken voor ons prototype.

Voor onze teddybeer hebben we drie belangrijke onderdelen nodig: Speech-to-Text, een Large Language Model en Text-to-Speech.

01 / STT

Speech-to-Text

Zet de gesproken vraag van het kind om naar tekst.

02 / LLM

Language Model

Verwerkt de vraag en genereert een antwoord.

03 / TTS

Text-to-Speech

Zet het gegenereerde antwoord om naar spraak.

Waar heb ik op gelet?

Bij het vergelijken van de modellen heb ik onder andere gekeken naar snelheid, taalondersteuning en de benodigde rekenkracht.

Omdat we de AI op onze eigen laptops wilden testen, was het belangrijk om rekening te houden met de prestaties van de modellen. Een model kan goede antwoorden geven, maar als het te langzaam reageert, is het minder geschikt voor een interactieve teddybeer.

Mijn bevindingen heb ik verwerkt in een Word-document. Dit gaf ons een overzicht van de mogelijkheden en hielp bij het maken van technische keuzes.

05 / ONTWIKKELING

De LLM programmeren

Na het onderzoek ben ik samen met Thayna aan de slag gegaan met het ontwikkelen van de AI. Voor de LLM heb ik gebruikgemaakt van Ollama en het taalmodel qwen3:4b-instruct.

Met Ollama kunnen we het model lokaal uitvoeren en vanuit Python vragen naar het model sturen.

De teddybeer een persoonlijkheid geven

Een belangrijk onderdeel van mijn code is de system prompt. Dit zijn instructies die bepalen hoe het model zich moet gedragen.

Ik wilde dat de AI vriendelijk reageerde, eenvoudige woorden gebruikte en korte antwoorden gaf. Daarom heb ik de volgende instructies opgesteld.

TEDDY_INSTRUCTIONS PYTHON 
TEDDY_INSTRUCTIONS = """
You are a friendly teddy bear talking to a child.
Always respond in English.
Use simple words and one or two short sentences.
Do not use emojis or markdown.
If you don't know something, say so.
"""

Met deze instructies probeer ik ervoor te zorgen dat de antwoorden passen bij onze doelgroep. Voor deze versie heb ik gekozen voor Engelse antwoorden.

Communiceren met het taalmodel

Vervolgens heb ik een functie gemaakt waarmee een vraag naar het taalmodel wordt gestuurd. De LLM genereert daarna een antwoord.

ask_teddy() PYTHON 
response = chat(
    model="qwen3:4b-instruct",
    messages=conversation,
)

answer = emoji.replace_emoji(
    response.message.content, replace=""
).strip()

De functie chat() stuurt het gesprek naar het model. Vervolgens haal ik het gegenereerde antwoord op en verwijder ik eventuele emoji's.

06 / EXPERIMENTEREN

Testen & problemen oplossen

Nadat de eerste versie van de LLM werkte, heb ik deze getest met verschillende vragen. Hierbij keek ik of het model begrijpelijke antwoorden gaf en zich aan de instructies hield.

Test 1: Gedrag van de teddybeer

Een van de vragen die ik gebruikte om het gedrag van de AI te bekijken, was wat de lievelingskleur van de teddybeer is.

VOORBEELD / AI-ANTWOORD

You: What is your favourite colour?

Teddy: My favourite colour is pink! It's soft and cuddly, just like me.

Dit antwoord past bij de persoonlijkheid van de teddybeer. Het is kort, vriendelijk en gebruikt eenvoudige taal.

Probleem 1: Emoji's in de antwoorden

Tijdens het testen merkte ik dat het model soms emoji's toevoegde, ook wanneer ik in de instructies had aangegeven dat dit niet moest.

Omdat we de antwoorden uiteindelijk willen laten uitspreken door een Text-to-Speech-model, wilde ik deze tekens verwijderen.

Daarom heb ik de Python-library emoji toegevoegd. Hiermee worden emoji's automatisch uit het gegenereerde antwoord gefilterd.

Probleem 2: Geen gesprekscontext

Een ander probleem was dat het model eerdere berichten niet automatisch onthield.

Als een kind een vervolgvraag stelde, had de LLM niet altijd de informatie uit het vorige bericht.

Daarom heb ik de code uitgebreid met gespreksgeheugen. Dit was een belangrijke verbetering ten opzichte van de eerste versie.

07 / ITERATIES

Gespreksgeheugen toevoegen

In de eerste versie kon de LLM vragen beantwoorden, maar werd de gespreksgeschiedenis niet bijgehouden.

Om dit op te lossen heb ik de Python-code aangepast. Nu worden zowel de vragen als de antwoorden opgeslagen in een lijst met berichten.

Hoe werkt het?

Conversation memory PYTHON 
messages.extend([
    {"role": "user", "content": question},
    {"role": "assistant", "content": answer},
])

Met messages.extend() voeg ik de nieuwe vraag en het antwoord toe aan de gespreksgeschiedenis. Deze berichten worden bij de volgende vraag opnieuw meegestuurd naar het model.

Test 2: Gespreksgeheugen

Om deze functionaliteit te controleren, kun je bijvoorbeeld de volgende test uitvoeren.

VOORBEELD / MEMORY-TEST

You: My name is Sara.

Teddy: Nice to meet you, Sara!

You: What is my name?

Teddy: Your name is Sara!

Dit voorbeeld laat zien wat het doel van gespreksgeheugen is: de teddybeer kan informatie uit eerdere berichten gebruiken bij het beantwoorden van vervolgvragen.

Een gesprek resetten

Naast gespreksgeheugen heb ik ook een resetfunctie toegevoegd. Hiermee kan een gebruiker een nieuw gesprek beginnen zonder de eerdere berichten.

reset_conversation() PYTHON 
def reset_conversation():
    messages[:] = [
        {"role": "system", "content": TEDDY_INSTRUCTIONS}
    ]

Wanneer de gebruiker 'reset' invoert, wordt de geschiedenis gewist en blijven alleen de oorspronkelijke instructies over.

Ook heb ik ervoor gezorgd dat het programma kan worden afgesloten met commando's zoals 'bye', 'goodbye' of 'exit'.

10 / REFLECTIE

Mijn reflectie

Deze sprint vond ik het leuk om samen met Thayna aan de AI te werken. Vooral het moment waarop de LLM goed begon te reageren, vond ik leuk om te zien.

Tijdens het programmeren merkte ik dat het werkend krijgen van een taalmodel pas de eerste stap is. Daarna moet je nog testen hoe het model reageert, welke instructies goed werken en hoe je ervoor zorgt dat het een natuurlijk gesprek kan voeren.

Door de problemen met emoji's en gespreksgeheugen op te lossen, kreeg ik een beter beeld van hoe belangrijk testen en verbeteren is tijdens het ontwikkelen.

Ik vond het ook interessant om te zien hoe de technische kant van ons project aansluit op de ethische vragen die we eerder hadden onderzocht.

We willen een teddybeer maken die vriendelijk reageert en kinderen helpt, maar tegelijkertijd moeten we nadenken over de invloed die zo'n AI kan hebben.

Wat ik de volgende keer beter wil doen, is vaker tussendoor updates geven aan mijn team. Bijvoorbeeld via Teams of GitLab wanneer ik nog ergens mee bezig ben, in plaats van pas wanneer ik een taak helemaal heb afgerond.

Deze sprint heeft mij laten zien hoe onderzoek, programmeren en samenwerken samenkomen bij het ontwikkelen van een prototype. Ik ben blij dat mijn bijdrage ook echt terug te zien was in het eindresultaat.
